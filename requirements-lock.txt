# HOW TO USE IT (an ISOLATED venv, without --system-site-packages)
#   py -3.10 -m venv .venv
#   .venv\Scripts\python -m pip install --upgrade pip setuptools wheel
#   .venv\Scripts\python -m pip install -r requirements-lock.txt
#
# CAREFUL: install.bat / install.sh create the venv with --system-site-packages
# (it inherits the global torch). That mode also inherits diffusers, accelerate,
# numpy and pillow from the global one, so versions nobody chose and shared with
# the other forks. For a reproducible venv, create it by hand as above rather
# than through install.bat.
#
# DO NOT regenerate this file from a `pip freeze` of a --system-site-packages venv:
# it captures the whole global site-packages (comfy-cli, yt-dlp...), a set pip

# AI provenance (EU AI Act art. 50): reads the C2PA manifests + the invisible
# TrustMark watermark, in PNG Info and through --provenance. CPU only (~0.1 s per
# image, the GPU is never touched); the TrustMark model (~40 MB) downloads on the
# first use. Windows: pip has to build trustmark's sdist, whose setup.py crashes on
# cp1252 -> install with PYTHONUTF8=1. Without these two, the Provenance section
# says "check unavailable" and no watermark can be written or read.

# 🖐 Detail hands: ultralytics and onnx are used ONCE, in a SUBPROCESS, to export the
# YOLOv8 hand detector (~6 MB, pulled from Bingsu/adetailer) to ONNX in cache/. They are
# never imported inside the app process: loading the torch YOLO model there corrupts the
# shared model weights during the offload transfers (renders turn to mosaic then NaN,
# proven by checksum - see cz_detailer._ensure_hand_onnx). At run time the detection uses
# onnxruntime only, pinned above. Without these two the hands pass stays unavailable and
# says so. torchvision, which ultralytics needs, is already pinned from the cu128 index
# next to torch: resolved from PyPI it comes built against a stock torch and every vision
# import dies on "operator torchvision::nms does not exist".
ultralytics==8.4.126
onnx==1.22.0
